# JavaScriptチャートライブラリ調査結果

**調査日**: 2025年10月25日
**目的**: ゴールド相場情報表示システムへのグラフ表示機能追加

## エグゼクティブサマリー

時系列データの折れ線グラフ表示を目的として、軽量・高速・評判の良いJavaScriptチャートライブラリを調査しました。

**推奨**: **uPlot** を第一候補とする
- 最軽量（47.9 KB）
- 最速（166,650ポイントを25msで描画）
- 時系列データに特化
- このプロジェクトの要件に最適

---

## 調査対象ライブラリ

### 1. uPlot ⭐⭐ 最推奨

#### 基本情報
- **公式サイト**: https://github.com/leeoniya/uPlot
- **バンドルサイズ**: 47.9 KB (minified)
- **ライセンス**: MIT

#### 特徴
- ✅ **超軽量**: 47.9 KBで最小クラス
- ✅ **最高速**: 166,650データポイントを25msで描画
- ✅ **メモリ効率**: ヒープピーク21MB、最終3MB
- ✅ **時系列特化**: 日付/時刻データに最適化
- ✅ **リアルタイム対応**: 高速更新に適する
- ✅ **レスポンシブ**: 自動リサイズ対応

#### 対応チャート種類
- 折れ線グラフ (Line)
- エリアチャート (Area)
- OHLC（ローソク足）
- バーチャート (Bar)

#### パフォーマンスベンチマーク
```
描画速度: 34ms
メモリ使用: 21MB (ピーク) → 3MB (最終)
処理速度: ~100,000 pts/ms (ウォームアップ後)
```

#### 長所
- 圧倒的なパフォーマンス
- 小さいバンドルサイズ
- ゼロ依存（Pure JavaScript）
- Canvas描画で高速

#### 短所
- チャートタイプが限定的
- カスタマイズ性はChart.jsより低い
- ドキュメントがやや簡素

#### 適用シナリオ
✅ **このプロジェクトに最適**
- 時系列データ（過去30日の価格推移）
- 折れ線グラフで十分
- 軽量・高速が重要
- シンプルな実装

---

### 2. Chart.js ⭐ バランス型代替案

#### 基本情報
- **公式サイト**: https://www.chartjs.org/
- **バンドルサイズ**: 71.3 KB (minified + gzipped)
- **ライセンス**: MIT

#### 特徴
- ✅ **バランスが良い**: 軽量と機能のバランス
- ✅ **豊富なチャート**: 8種類以上のチャートタイプ
- ✅ **ドキュメント充実**: 公式ドキュメントが詳細
- ✅ **コミュニティ**: 最も人気が高く、情報が豊富
- ✅ **Canvas描画**: SVGより高速

#### 対応チャート種類
- 折れ線、棒、円、ドーナツ、レーダー、極座標、バブル、散布図など

#### パフォーマンス
```
小〜中規模データ: 良好
大規模データ: パフォーマンス低下の可能性
レンダリング: Canvas（高速）
```

#### 長所
- 使いやすいAPI
- 多様なチャートタイプ
- 豊富なプラグイン
- アニメーション対応

#### 短所
- uPlotより若干重い（71.3 KB）
- 大規模データではuPlotに劣る
- Tree-shakingが限定的

#### 適用シナリオ
- 多様なチャートタイプが必要
- カスタマイズ性重視
- ドキュメント・サポート重視

---

### 3. ECharts - 高機能・エンタープライズ向け

#### 基本情報
- **公式サイト**: https://echarts.apache.org/
- **バンドルサイズ**: 354 KB (minified + gzipped)
- **ライセンス**: Apache 2.0

#### 特徴
- ✅ **大規模データ対応**: 数十万ポイントを高速処理
- ✅ **豊富な機能**: 50種類以上のチャート
- ✅ **Canvas/SVG両対応**: 用途に応じた選択可能
- ✅ **インタラクティブ**: 高度な操作性
- ✅ **エンタープライズ**: Apache財団管理

#### パフォーマンス
```
大規模データ: 優秀
レンダリング: Canvas/SVG選択可
データストリーミング: 対応
インクリメンタルレンダリング: 対応
```

#### 長所
- 大規模データに強い
- 極めて多機能
- エンタープライズ品質
- 詳細なカスタマイズ可能

#### 短所
- バンドルサイズが大きい（354 KB）
- 学習コストが高い
- オーバースペック（このプロジェクトには）

#### 適用シナリオ
- 大規模データ分析
- 複雑な可視化要件
- エンタープライズアプリケーション

## このプロジェクトでの評価

### 要件分析

#### データ特性
- **データ種類**: 時系列データ（日次）
- **データ量**: 過去30日分（30ポイント × 4系列 = 120ポイント）
- **更新頻度**: 1日1回
- **表示内容**: 折れ線グラフ

#### 技術要件
- **軽量性**: 重要（ゼロ依存方針）
- **パフォーマンス**: 小規模データのため、どのライブラリでも十分
- **シンプルさ**: 重要（Pure HTML/JS/CSS）
- **チャートタイプ**: 折れ線グラフのみで十分

### スコアリング

| 評価項目 | uPlot | Chart.js | ECharts |
|---------|-------|----------|---------|
| 軽量性 | 10/10 | 9/10 | 5/10 |
| パフォーマンス | 10/10 | 8/10 | 9/10 |
| 使いやすさ | 7/10 | 10/10 | 6/10 |
| ドキュメント | 6/10 | 10/10 | 8/10 |
| 機能適合性 | 10/10 | 10/10 | 7/10 |
| **総合** | **43/50** | **47/50** | **35/50** |

### 最終推奨

#### 第一候補: **uPlot**

**選定理由**:
1. **最軽量**: 47.9 KBでゼロ依存方針に最適
2. **最高速**: パフォーマンスが圧倒的
3. **時系列特化**: プロジェクトの用途に完璧にマッチ
4. **シンプル**: 必要十分な機能のみ
5. **メモリ効率**: ブラウザリソース節約

**懸念事項**:
- ドキュメントがChart.jsより少ない
  → 実装例が豊富で問題なし
- カスタマイズ性がやや低い
  → 基本的な折れ線グラフには十分

#### 第二候補: **Chart.js**

**条件付き推奨**:
- より多様なチャートタイプが将来必要になる場合
- ドキュメント・サポートを重視する場合
- 71.3 KBも十分軽量

## 実装ガイドライン

### uPlot採用時の実装方針

#### 基本設定
```html
<!-- CDN -->
<link rel="stylesheet" href="https://unpkg.com/uplot/dist/uPlot.min.css">
<script src="https://unpkg.com/uplot/dist/uPlot.iife.min.js"></script>
```

#### データ構造
```javascript
// uPlotのデータ形式
let data = [
  [timestamps],  // x軸（Unix timestamp）
  [spot_prices], // 系列1: スポット価格
  [etf_prices],  // 系列2: ETF価格
  [forex_rates], // 系列3: 為替レート
];
```

#### オプション例
```javascript
let opts = {
  title: "ゴールド相場推移",
  width: 800,
  height: 400,
  series: [
    { label: "日付" },
    { label: "スポット", stroke: "red" },
    { label: "ETF 1540", stroke: "blue" },
    { label: "USD/JPY", stroke: "green" },
  ],
  axes: [
    { label: "日付" },
    { label: "価格" },
  ],
};
```

### 注意事項

1. **CORSエラー対策**: 既に実装済み（JSファイル読み込み方式）
2. **レスポンシブ対応**: uPlotは自動対応
3. **アニメーション**: デフォルトでは無効（CLAUDE.mdの方針に適合）
4. **データ更新**: 再描画で対応

## まとめ

ゴールド相場情報表示システムのグラフ機能追加には、**uPlot**を推奨します。

軽量（47.9 KB）、高速、時系列データに特化しており、プロジェクトの要件に完璧に適合します。シンプルな実装で、既存のゼロ依存・Pure JavaScript方針を維持しながら、優れたユーザー体験を提供できます。

将来的により多様なチャートタイプや高度なカスタマイズが必要になった場合は、Chart.jsへの移行も容易です。
